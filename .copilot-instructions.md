# Copilot Agent Instructions for OrderedLinqOps

## Mission

Keep changes correct, streaming-first, and maintainable:
- No unnecessary buffering
- No accidental public API breaks
- No stale comments or docs
- No framework assumptions beyond the repository target frameworks

Use `src/OrderedLinqOps/OrderedLinqOps.csproj` as the source of truth for target frameworks.

## Review Scope

CI already checks mechanical gates (build/test/changelog/XML-doc gate).  
Your review should focus on quality:
- Correctness and ordering validation behavior
- Streaming and memory behavior
- Backward compatibility
- Pattern consistency with existing operators
- Documentation/comment accuracy

Use `CODE_REVIEW_CHECKLIST.md` as the checklist and `CONTRIBUTING.md` for standards.

## Review Communication

When you begin a review, post a short status comment immediately: `Starting automated code review...`
When the review concludes, post a final status comment: `Automated code review complete.`
If the review finds issues, summarize the main findings and file references; if none are found, state that no blocking issues were identified.

These status comments should appear on the PR timeline so the request is clearly distinguishable from the initial trigger comment.

## When Proposing Code

- Follow conventions derived from existing operators in `src/OrderedLinqOps/`.
- Keep changes small and explicit.
- Add or update tests for behavior changes.
- Update CHANGELOG when user-facing behavior changes.
