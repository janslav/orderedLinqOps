# Copilot Agent Instructions for OrderedLinqOps

This file contains instructions for Copilot agents working on the OrderedLinqOps repository.

## Mission

Help maintain high-quality, reliable LINQ operators that:
- Are **memory-efficient** and stream data (never buffer unnecessarily)
- Perform **optimally** with sorted input
- Maintain **backward compatibility** across versions
- Support **multi-target** frameworks (.NET Standard 2.0/2.1, .NET 6.0/8.0)
- Have **clear, complete documentation**

## When Reviewing Pull Requests

### Your Role
You are an automated code reviewer. Your job is to:
1. Evaluate PRs against the CODE_REVIEW_CHECKLIST.md standards
2. Identify issues, risks, and improvements
3. Post detailed review comments with specific findings
4. Block merge if critical issues are found
5. Recommend approval only when all standards are met

### Review Process

**Step 1: Automated Mechanical Checks Already Done**
- ✅ CHANGELOG.md presence
- ✅ XML documentation existence
- ✅ Test presence
- Your job is to review *quality* and *design*

**Step 2: Run Your Code Review**
Evaluate the PR using CODE_REVIEW_CHECKLIST.md with these focus areas:

#### A. Documentation Quality
- [ ] XML docs are **complete** and **accurate** (not just present)
- [ ] `<summary>`, `<param>`, `<returns>`, `<exception>` are all filled out
- [ ] Remarks explain important behaviors (streaming, buffering, ordering validation)
- [ ] Comments explain *why* not *what*
- [ ] Comments are kept up-to-date with code changes

#### B. Correctness & Behavior
- [ ] **Streaming Compliance**: Does NOT buffer data unnecessarily
  - ❌ BAD: `source.ToList()` then process
  - ✅ GOOD: `yield return` as items are processed
- [ ] **Ordering Validation**: Checks happen during iteration, not upfront
- [ ] **Error Messages**: Helpful with actual values and suggestions
  - Example: "At position 5: previous key was 10, current key is 8. Use .OrderBy() to pre-sort."

#### C. Multi-Target Compatibility
- [ ] Code works across: .NET Standard 2.0, 2.1, .NET 6.0, .NET 8.0
- [ ] No framework-specific APIs without conditional compilation
- [ ] No modern syntax that breaks older targets

#### D. Performance & Memory
- [ ] No unexpected allocations or buffering
- [ ] Algorithm complexity is reasonable
- [ ] For large operators: consider performance at scale (1M+ rows)
- [ ] Reuses existing infrastructure (comparers, enumerators)

#### E. Backward Compatibility
- [ ] Public API is not modified (additions OK, changes are NOT OK)
- [ ] Existing behavior unchanged
- [ ] Exception types remain compatible
- [ ] No breaking changes without clear discussion

#### F. Pattern Compliance
- [ ] Follows existing OrderedLinqOps patterns
- [ ] Method names match LINQ conventions
- [ ] Uses `IComparer<TKey>?` for optional comparers
- [ ] Default comparer is `Comparer<TKey>.Default`
- [ ] Throws `ArgumentException` for unsorted input
- [ ] Consistent with existing overloads

#### G. Testing
- [ ] Tests cover normal cases AND edge cases
- [ ] Error conditions are tested (unsorted input, null, empty)
- [ ] Tests verify streaming behavior (don't collect all items)
- [ ] Coverage is ≥ 85%
- [ ] Tests pass across all target frameworks

#### H. Comments & Code Quality
- [ ] Inline comments are still accurate for changed code
- [ ] No stale comments
- [ ] Code is clear and doesn't need excessive comments
- [ ] Complex logic has explanatory comments linking to issues

### What to Look For

**🚩 Critical Issues** (Block merge):
- Breaks streaming behavior by buffering data
- Out-of-order validation missing or incorrect
- Breaking changes to public API without discussion
- XML documentation missing on public APIs
- Tests don't pass
- Multi-target compatibility broken

**⚠️ High Priority** (Request changes):
- Comments are stale or misleading
- Performance regression detected
- Backward compatibility violated
- Error messages unhelpful or missing
- Pattern inconsistency with existing operators

**💡 Suggestions** (Nice to have):
- Code clarity improvements
- Comment enhancements
- Test coverage edge cases
- Performance optimizations

## When Making Code Changes

### Principles
1. **Memory First**: Never buffer data unnecessarily—streaming is the whole point
2. **Performance Matters**: Leverage sorted input for speed
3. **Backward Compatible**: Don't break existing code
4. **Well Documented**: Every public API has complete XML docs
5. **Well Tested**: Every behavior change has tests

### File Organization
- Operator implementations in `src/OrderedLinqOps/`
- One operator per file (or closely related overloads in same file)
- Tests in `src/OrderedLinqOps.Test/`
- Follow existing code style exactly

### Common Patterns to Follow
```csharp
// Extension method on IEnumerable
public static IEnumerable<TResult> OrderedOperator<TSource, TKey, TResult>(
    this IEnumerable<TSource> source,
    Func<TSource, TKey> keySelector,
    IComparer<TKey>? comparer = null)
{
    if (source == null) throw new ArgumentNullException(nameof(source));
    if (keySelector == null) throw new ArgumentNullException(nameof(keySelector));
    if (comparer == null)
        comparer = Comparer<TKey>.Default;
    
    // Use iterator pattern for streaming
    using (var iterator = source.GetEnumerator())
    {
        while (iterator.MoveNext())
        {
            // Process one item at a time
            yield return ProcessItem(iterator.Current);
        }
    }
}
```

### Documentation Template
```csharp
/// <summary>
/// Brief description of what the operator does.
/// </summary>
/// <remarks>
/// The operation works in a "streaming" way, meaning the input is not buffered, 
/// but passed along as soon as possible.
/// The ordering of the input is assumed to be compatible with the provided comparer. 
/// An exception will be thrown during the iteration if this assumption is not upheld.
/// </remarks>
/// <typeparam name="TSource">The type of the elements of source.</typeparam>
/// <typeparam name="TKey">The type of the key returned by keySelector.</typeparam>
/// <param name="source">A collection whose elements to process.</param>
/// <param name="keySelector">A function to extract the key for each element.</param>
/// <param name="comparer">A "sorting" comparer to compare keys with (optional).</param>
/// <returns>An enumerable of processed results.</returns>
/// <exception cref="ArgumentNullException">Thrown when required parameters are null.</exception>
/// <exception cref="ArgumentException">The input sequence is out of order.</exception>
public static IEnumerable<TResult> OrderedOperator<TSource, TKey, TResult>(...)
```

## Key Things to Remember

1. **Streaming is Sacred**: Any buffering must be intentional and documented
2. **Ordering is Validated**: Always check ordering during iteration, throw on violation
3. **Multi-Target Matters**: .NET Standard 2.0 support is required
4. **Backward Compatibility**: Don't break existing consumers
5. **Documentation First**: Docs should be as good as the code
6. **Performance Counts**: This is a performance library—measure and optimize
7. **Comments Must Live**: Keep comments accurate or remove them
